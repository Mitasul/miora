# 2026-10-16：重复检查与防御性代码清理

范围：Rust 配置/运行时、插件安装与执行、参数构造、原生和通用转发、观测与统计、请求日志，以及整个 `assets/admin` 后台。按实际调用链判断是否重复，不按 `if`、`Result` 或 `Option` 的数量机械删除。

## 后续开发操作约束

用户反馈 Windows 验证时反复弹出可执行文件控制台。原因是 Python 启动网关等子进程时未指定隐藏控制台；预览、HTTP、浏览器回归、性能和运维脚本的启动入口现统一指定 Windows `CREATE_NO_WINDOW`，非 Windows 保持 `creationflags=0`。本地忽略目录中的预览启动器同步修改，不再依赖父进程分离来隐藏子进程。

本次后续修改只检查源码及启动参数，不运行网关、浏览器或部署脚本，不重启预览，不执行哈希核对。新增静态合约测试只解析 Python 源码及计算启动标志，不启动被检查的程序。此前的运行时测试结果属于上一轮清理，不能视为本次改动后的运行结果。后续开发约束记录在项目 `AGENTS.md`。

## 本轮删除

- 流式响应不再抽样计算内容 SHA-256；删除每请求采样、每 chunk 更新、终止时摘要克隆/编码以及对应环境变量和报告字段。字节、chunk、用量和阶段计时保留。
- HTTP 错误回执不再计算正文 SHA-256。保留有界、脱敏的错误字段与真实回执 ID；没有事实导出器时不再构造随后丢弃的回执 JSON。
- 插件文件解码只负责 JSON/包格式；完整 manifest、服务信任、认证和配置校验集中在候选创建处。健康探测及探测成功后的发布不再重新构造、复制和校验同一份候选。
- 插件历史版本已在写入和启动时验证，回滚不再遍历重验它。健康探测后仍在锁内复核修订号和全局安装容量，避免并发覆盖或越过安装上限。
- 上传文件名没有作为磁盘路径使用，删除文件名字符黑名单。包内容决定能否安装；不执行上传代码，不新增压缩包或代码托管协议。文件/请求体容量限制仍在各自边界生效，文件上限只检查一次。
- 插件前端只解析 JSON、识别 Miora 包格式及预览所需的 ID/名称/版本。不再在浏览器重写一套完整的服务地址、信任、schema、认证和配置校验；安装由同源后端统一判定和返回错误。读取文件前保留容量检查。
- 参数构造的 body 阶段已完成策略结构校验，紧接的 header 阶段不再重新遍历整个策略；没有启用 header 规则时不转换整张原生请求头。无插件拦截器时也不做无效的请求头往返解析。
- 后台直接使用同源接口约定的渠道、插件、版本、密钥、统计、审计及日志字段数组，不再逐层 `Array.isArray ? value : []`，避免契约错误被掩盖成“空数据”。新建表单、接口失败、历史缺失指标所需的空值处理仍保留。
- 请求预览固定使用后端的 `policy_trace` 和 `policy_report.warnings`，删除不存在的旧形状回退；直接显示服务端已脱敏的请求头，不再次按名称复制和脱敏。
- 删除模型目录和日志设置的同源响应形状复验。日志清理不再兼容不存在的 `skipped_rows` 数组形态，也不再用浏览器时钟重复裁定服务端确认 token 是否过期。
- 删除日志详情和文本预览的重复响应结构校验。内容已过期、被清理或丢失时，后端返回 404/410，由统一 API 错误处理与现有详情刷新流程处理，不再另外猜测成功响应是否失败。

## 保留的边界

- 登录密码派生、会话认证、CSRF、源限制、凭据脱敏和 AWS 等协议要求的签名不是内容完整性哈希，不删除。
- 不把凭据标识、幂等去重、不可变配置快照标识和协议签名替换成明文秘密，也不增加上传/发布的内容校验和。
- HTTP/JSON 解析、源文件和用户输入校验、第三方上游解析、终止帧语义检查、未知指标与真实零值的区别属于实际数据边界，不改成假成功。
- 配置原子写入、并发修订检查、回滚、请求取消、超时、重试预算、背压及磁盘/内存上限继续生效。
- 从源文件直接加载的参数策略仍可能无效，因此 body 阶段保留一次完整结构校验；没有通过新增验证标志、泛化校验框架或额外缓存掩盖该边界。
