## 已核实并补齐

| 对照发现 | 原有缺口 | Miora 本轮实现 |
| --- | --- | --- |
| 模型趋势和渠道分析 | 概览只能看模型总计，无法按时间或渠道比较 | 一次用量请求返回总计、模型、渠道、小时/天趋势；输入、输出、缓存、失败数与费用可切换，不增加图表库 |
| 日志和统计按相同条件分析 | 从概览进入日志时只保留模型，丢失渠道与时间 | 模型/渠道名称和趋势柱携带固定的渠道、公开模型、起止毫秒；边缘时间桶裁到实际查询区间；日志表单展示本地时间并保留毫秒 |
| 渠道复制 | 只能从头填写；用脱敏表单复制会丢失凭据和秘密 URL | 仅填写新名称，服务端从源配置复制完整渠道，保留别名、模型价格、插件配置与凭据，不把秘密返回浏览器 |
| 渠道筛选与分析入口 | 只搜名称/模型，没有接入方式筛选与统计入口 | 本地组合筛选名称/模型/地址及接入方式；渠道行直接进入该渠道的概览统计 |
| 失败请求的渠道归属 | 通用转发重试耗尽后的请求汇总漏存渠道名，导致渠道统计少算失败 | 顺序重试与并发尝试耗尽时记录最后实际失败的渠道和上游模型；一次客户端请求只计一次，物理尝试仍单独记录；历史缺失渠道保持未知，不推测回填 |

所有统计分组共享同一个筛选 CTE，不重复扫描请求正文，不额外查询每个模型或每个渠道。分组和图表指标切换只使用已返回的数据，不发网络请求。模型与渠道各自最多展示 500 项，总计与趋势不受该展示上限影响。数据库未记录的缓存/价格仍为未知，不补成零，不按当前单价重算历史请求。

## 删减与保留

- 删除品牌图的 SHA-256 来源属性与摘要校验，不增加上传完整性哈希或发布后哈希核对。
- 本地源配置的保存冲突令牌改用修改时间和文件长度，不再为每次后台读写计算文件摘要；保留原子保存、共享写锁和冲突提示，避免多表单互相覆盖。
- 删除日志列表对同源后端分页结构的重复逐字段校验；HTTP/JSON 错误仍由统一 API 客户端处理。
- 复制已保存渠道不再重复校验所有未变字段；新名称仍须唯一，发布仍经过现有配置编译。
- 保留必要的登录认证、CSRF、用户输入解析、资源预算、日志脱敏与取消请求；不把密码派生、会话标识或内容寻址误当作文件完整性校验来删除。

## 工作区、后台日志、实测与密钥分组补充

继续对照本机参考快照的 `pages/Workspace.tsx`、`routes/workspace.py`、`pages/BackendLogs.tsx`、`pages/Admin.tsx` 及渠道与 API Key 测试组件，仅参考管理流程，不复制实现、样式或插件协议。

- 工作区：按目录浏览 `docs`、`examples` 和 `plugins` 下的文本文件；文档与插件文件只读。源配置以虚拟文件 `config.yaml` 打开，管理员确认后可查看原始凭据、编辑和下载。保存经过现有配置编译与发布流程，并保留 YAML 注释；使用修改时间与长度修订号处理并发修改，不计算内容摘要、不创建备份。远程配置只读并脱敏；运行状态与插件列表为只读虚拟文件。数据库、环境文件和任意磁盘路径不开放。
- 后台日志：接入网关启动、配置加载/错误和现有请求事件；与请求正文日志、管理审计分开。内存环形缓冲保留最近 2000 条，支持级别、关键词、Request ID 搜索和增量读取；浏览器最多显示 500 条，隐藏或离开页面停止更新，无重叠轮询。日志不跨网关重启保存，也不冒充完整系统 stdout/stderr 收集器。
- 实测：使用已保存的启用 API Key，在网关进程内走实际推理链路，不向浏览器返回密钥。支持 Chat Completions / Responses 的非流式单模型测试、串行批量测试、停止后续测试、HTTP 状态、耗时、输入/输出/缓存 Token、原始响应和请求日志下钻。不会在打开页面时自动测试，也不默认设置输出 Token 预算。精确渠道诊断沿用现有权限边界：管理员 API Key + Responses，不重试、不回落。普通 Key 按真实模型规则与分组路由。真实测试可能计费，本轮开发未执行付费测试。
- 密钥与分组：支持名称、多分组、角色、模型规则、速率限制、持久化启停和吊销；从所属分组载入模型，支持本地筛选。渠道编辑器直接设置相同分组。分组不只是标签：运行时按 Key/渠道分组交集，再结合模型授权筛选；嵌套 Key 不得扩张上层分组权限。未配置分组的旧条目属于 `default`。停用 Key 保留源配置和统计，仅从可认证的运行时凭据中移除。

本轮只运行静态与纯模块检查，不启动或重启网关，不执行浏览器或会启动插件进程的回归测试。已嵌入可执行文件的前端资源仍需由用户安排下一次构建与启动才会更新。
