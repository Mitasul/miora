# Miora 第一轮盘点与分期差距

状态：基于当前开发工作区的源码盘点，不是全部目标已实现的声明。

后续说明：本页是第一轮历史盘点，表中部分缺口已在后续实现。2026-10-16 实际对照本地 Zoa 源码后的补缺范围与未完成项，见 [Zoa 对照记录](zoa-comparison.md)。下文「没有读取源码」仅描述第一轮，不代表后续仍未对照。

本轮依据 Miora 自有代码与用户给出的行为要求进行独立设计。没有读取或移植 Zoaholic 的源码、组件、测试或文档。本轮不重写 Rust 网关、不更改生产服务、不自动重启当前预览。Apache-2.0 许可证与 uni-api 归属继续保留。

## 先用通俗话说

- **已有**：Rust 网关的协议转换、路由、凭据轮询、冷却、重试、超时；管理员后台；渠道/访问 Key 管理；模型发现和别名；能在运行时注册的独立 HTTP 插件及版本切换。
- **缺少**：插件代码包安装与进程托管、使用中卸载保护、完整处理插件、七页渠道编辑器、真实调试台、完整请求正文日志与留存清理、通用 OAuth/额度插件接口。
- **先做什么**：保留现有主链路，补一个确实访问上游的独立渠道插件样例，先证明注册、模型发现、JSON/SSE、版本切换和取消能贯通。Echo 只算测试夹具，不算真实上游接入。

## 四个概念必须分开

| 概念 | 含义 | 当前落点与差距 |
| --- | --- | --- |
| 渠道类型 | 接入协议和实现，例如 Chat Completions、Messages、Responses、特殊 OAuth 图片协议 | 当前 `engine` 与插件 ID 承担此角色；部分供应商名称混在类型里，需逐步转为协议类型和配置模板。 |
| 渠道实例 | 用户保存的地址、凭据、模型、参数和调度配置 | `providers` 中的一项；当前名称兼任路由标识，缺独立稳定 ID。 |
| 渠道插件 | 增加渠道类型、认证、发现、传输和响应处理能力 | `src/plugins/` 已支持独立服务，内置 Rust 模块只是另一种实现，不能把它叫动态代码包。 |
| 处理插件 | 对选定渠道请求/响应执行一个小补丁 | 当前只有独立的请求头规则，按插件 ID 筛选；尚无按渠道实例启用的请求体处理链。 |

OpenAI 兼容供应商应创建通用渠道实例。OpenRouter、DeepSeek 等供应商信息通常应成为默认地址/参数模板，而不是仅因品牌不同新增插件。当前六类菜单是阶段性界面目录，不是最终类型系统。

## 日志和业务结果的具体差距

原生 Responses 已区分终止事件、预算不足、断流和 tool-only 完成，不需要从零重写。必须继续区分：

- `http_status`：HTTP 层状态。
- `business_result`：正常完成、工具调用、预算不足、半途断流、取消或其他错误。
- `upstream_complete`：是否看到上游的终止证据。
- `relay_complete`：网关是否完整交付响应流给 HTTP 发送层。
- `client_received_complete`：无法证明时必须是 unknown，不能用服务端完整记录代替客户端已收到。

新的请求记录需分别保存 `requested_model`、`sent_model`、`response_model`。现有 request/model/upstream_model 字段不等于三个字段已经完整。

正文对象至少记录 `original_bytes`、`saved_bytes`、`reason`、`completeness`、可下载对象引用。未知原始总长度应为 unknown，而不是把截断位置误记为总长度。原始包体 0 小时表示不捕获，不影响统计行；清理正文只移除对象和其可下载状态，保留统计摘要。现有 spool 主要服务请求重放，不可直接改名冒充日志保留系统。

## 分期与本轮实际范围

### 阶段一：动态链路与独立设计

本轮：差距表、动态扩展选型/接口草案、许可证声明清单，以及独立真实转发样例。只走一个 Chat 类型的模型发现、JSON 与 SSE；复用现有管理认证和注册表。样例真实转发请求，测试上游是明确标注的本地 fixture。

本轮不实现：代码包上传安装、进程托管、卸载、全部 hook、OAuth、七页编辑器、日志系统和参数策略迁移。实现状态见样例 README 及交付结果，不把设计中的能力报为已完成。

### 阶段二：渠道管理与参数策略

稳定实例 ID；列表操作与七页框架；先落基础/模型/参数/调度/测试页；三态与删除契约；未知字段往返；草稿使用同一请求构造链；显示实际配置版本。参数分类和多浏览器保存测试在此阶段完成，不一次改写整个路由器。

### 阶段三：日志与留存

请求记录和正文对象分离；时间线与原始/解析/文本视图；正文超限完整性字段；四类限制；按条件预览/清理；安全下载、HTML/SVG 默认文本及隔离预览；运行日志轮转。清理正文不删除统计摘要。

### 阶段四：高级扩展

通用 OAuth、刷新/解除绑定、账号标识与额度；按渠道实例的处理插件流水线；受限 UI 扩展；特殊传输及更多协议。代码包管理和托管进程必须有单独执行权限边界，使用中的类型不允许直接卸载。

## 本轮实测结果

仅运行新增的定向脚本，最终退出码为 0：

```powershell
python -B tests/http/verify_real_channel_plugin.py target/x86_64-pc-windows-gnu/debug/uni-api-front.exe
```

本地隔离上游检查了实际收到的路径、方法、正文、鉴权头和请求次数；插件本身执行真实 HTTP 转发。通过项包括：

- 真实模型目录查询、独立服务认证、固定进程版本健康响应。
- 非流式 JSON 响应实体字节保留；有正文但无 usage；空文本但有 tool_calls。
- 客户端别名、上游发送名、上游响应名分别观察。
- 超过 2 MiB 的多块 SSE；Content-Length 正常与提前截断；断流不补造 DONE。
- 直接调用插件时的响应头前/静默上游取消，以及经网关的活跃/静默流取消；上游在测试门槛 2.5 秒内观察到关闭，而其读取超时配置为 120 秒。经网关的响应头前取消尚未覆盖。
- 两个独立版本进程切换时旧流完整完成，新请求使用新版本；错误健康版本不替换当前注册。
- 上游 429 仍为失败，服务和供应商凭据隔离。单次转发断言使用访问 Key 的 `AUTO_RETRY=false`，不改变宿主重试行为。

这不包含真实供应商生产兼容、WAN/TLS 取消、慢消费者资源占用量测、全协议工具多回合、参数策略迁移、日志留存或清理测试。长流转发通过不等于长响应日志保存通过。本轮没有重启现有预览或生产服务，也没有修改 Rust 执行器。
